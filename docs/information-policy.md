# 自動的な情報量検査と投稿の判定

## 検出方針

投稿そのものから、公開するには危険そうな文字列を機械的に検出する。
利用者が秘密値、顧客名、案件名、禁止語を事前登録することを前提にしない。
環境変数、認証情報ストア、私的ファイルを走査して秘密値一覧を作る処理も持たせない。
HMAC等による登録値との一致判定は、idobataの基本アルゴリズムに含めない。

入力はUTF-8のbyte列として扱い、言語判定、単語分割、言語別の形態素辞書、
人名・組織名の列挙に必須の処理を依存させない。
文字列の構造、局所エントロピー、公開データから得た予測しにくさ、周辺との差を併用する。
「固有名詞である」と意味分類できなくても、局所的に特異な文字列として警告できる設計にする。

この処理系に言語別の分岐を置かないことと、すべての言語で同じ精度を持つことは別である。
参照モデルには学習データの偏りが残る。十分に評価できない入力は警告して止める。

## 検査する範囲の自動抽出

原文と復号・正規化した検査用表現について、次を候補spanとして列挙する。

- 引用、代入、区切り、構造化フィールドの値。
- URLのuserinfo・ホスト・パス・クエリ・fragment。
- hex/Base64等の文字列、連続した識別子らしい部分、数字と記号の混在。
- 単語境界を仮定しない、複数の長さの重なり合う部分列。

日本語のように空白が少ない文章も、部分列の走査から外さない。
UTF-8の文字の途中で除去しないように、原文の文字境界とbyte位置を対応付ける。
構造的な候補抽出だけで全文の走査を置き換えない。
必要な走査が処理上限内に終わらなければ検査不能として止める。

## 測度1 局所エントロピー

候補span sに含まれるbyteの出現割合をp_s(b)として計算する。

```text
H(s) = - Σ p_s(b) log2 p_s(b)     [bit/byte]
```

ランダムなtoken、鍵、未解釈の識別子などを検出するための特徴量とする。
候補長、文字種、周囲の同程度の長さの部分列との差を合わせて扱う。
短い値では推定が不安定であり、長さによらない一つの閾値を使わない。
UTF-8の符号化上の特徴も値に影響するため、高いHだけで秘密と断定しない。

低エントロピーでも、後述する資格情報形式に該当すれば拒否する。
形式にも情報量異常にも現れない短い秘密を、確実に見つけられるとはしない。

## 測度2 公開参照モデルでの予測しにくさ

公開データだけから作成した固定のbyte単位参照モデルp_refを使い、候補の符号長を計算する。
ゼロ確率を避けるため、256種のbyteの一様分布を混合した正規化確率q_refを使う。
混合係数lambdaは0より大きく1より小さい固定値とし、校正してbundleに含める。

```text
q_ref(b | c) = (1 - lambda) * p_ref(b | c) + lambda / 256
L_ref(s) = - Σ_i log2 q_ref(b_i | b_1 ... b_(i-1))   [bit]
I_ref(s) = L_ref(s) / byte_length(s)                 [bit/byte]
```

一般的な表現より予測しにくい部分列では、I_refが大きくなる。
長さだけで珍しさが大きくならないように、総符号長L_refと平均I_refを分けて扱う。
公開された製品名や技術的識別子も高い値を取り得るため、この値は機密確率ではない。

参照モデルはbyte n-gramやbyte単位の確率モデル等から選定する。
言語別のtokenizerや固有名詞辞書を必須にせず、入力を評価するための確率だけを得る。
ByT5のようなbyte処理の研究は表現方式の参考であり、既存モデルをそのまま漏出検出器と
認定するものではない。モデル選定、符号長推定、閾値は実装前の評価が必要である。

投稿中の繰返しで秘密が一般語扱いにならないように、各候補を固定の開始状態から評価する。
同じ候補を何度繰り返しても、その初回や独立評価で得た高い値を消さない。
利用者の投稿、会話履歴、私的リポジトリを参照モデルへ追加学習しない。
入力文字列を外部検索や外部LLMへ送って、公開語かを確認する方式は使わない。

## 測度3 周辺との差と複数尺度での特異性

候補と同程度のbyte長の周辺span群W(s)を使い、局所差も計算する。

```text
Delta_I(s) = I_ref(s) - median { I_ref(w) : w in W(s) }
```

一般的な説明文の途中にだけ現れる未知の名前や識別子を検出する補助とする。
I_refの絶対値、H、構造上の特徴、複数の候補長での持続性と併せて判定する。
周辺全体が予測しにくい場合はDelta_Iが小さくても安全とは扱わない。
周辺が足りない場合は差を0で補完せず、利用不能な特徴量として扱う。

局所的な高い値を文全体の平均で相殺しない。
長い一般文を付け足したり、未知文字列を繰り返したりしても警告が消えないようにする。
直近の送信済み本文との連結も補助検査に使い、分割した識別子や値の再構成を検出する。

## 形式検査と判定順序

情報量に加えて、秘密鍵の構造、HTTP認証値、cookieの構造、URLの資格情報部分などを検査する。
これは利用者の秘密値を登録する照合とは異なり、値の内容を知らずに形式から検出する処理である。
個別サービスのprefixルールを補助に使っても、それがないと検出できない設計にはしない。
人名辞書にないことだけで拒否する処理は設けない。

| 順序 | 検査 | strict profileでの処理 |
| --- | --- | --- |
| 1 | 構造、サイズ、UTF-8、処理上限 | 不備・検査不能なら拒否 |
| 2 | 資格情報を示す明確な形式 | 内容のランダムさによらず拒否 |
| 3 | 内部経路や識別子を示す構造 | 警告して投稿失敗、または除去案 |
| 4 | 局所エントロピーの異常 | 警告して投稿失敗、または除去案 |
| 5 | 公開参照モデルでの特異性 | 警告して投稿失敗、または除去案 |
| 6 | 周辺・全文・直近投稿との組合せ | 警告して投稿失敗、または除去案 |

判定は、資格情報形式による拒否、特異性による警告、不確実性、合格を区別する。
単一の加重平均を計算し、低い特徴量で重大な検出を打ち消す方式にはしない。
秘密の種類や所有者を確定できなくても、特異性が高ければ機械的に止める。

## 符号化と正規化

原文と複数の検査用表現を保持し、検出spanから原文位置へ戻せるようにする。
UnicodeのNFKC、URL percent encoding、JSON escape、HTML entity、
Base64らしい候補の復号を検査に使う。NFKC表現でコード本文を勝手に書き換えない。

初期案では復号は最大3段、展開済みデータの合計は256 KiBまで。
上限に達したものは「検査済み」ではなく検査不能として投稿を止める。
復号候補数と総走査回数にも上限を持たせる。
ゼロ幅文字・bidi制御文字などの曖昧化は、初期版では拒否する。

長い入力の先頭だけを見て残りを送る処理はしない。
v1では添付を受け付けず、圧縮データやdata URLを投稿しない。
URLの検査では取得やDNS問い合わせを行わず、全成分を構造として解析する。
Markdownのリンク先やコード内のURLも同じ対象とする。

## 除去と再検査

`prepare --redact` は、検出された特異spanを `[REDACTED_1]` のような固定形式へ置換する。
人名・組織名と意味分類できることを除去の条件にしない。
番号は投稿ごとにデーモンが割り当て、元の値・長さ・hashから別名を作らない。
対応表をpeerへ送らず、除去markerをagentの任意データの格納場所にもさせない。

明確な資格情報形式を含む投稿は、この操作でも自動投稿しない。
診断に原文、先頭数文字、前後の未検査断片を混ぜない。
spanの重なりは原文位置で統合し、URL内の特異spanはURL全体へ除去範囲を広げる。

置換後の全文を再検査し、未解決の警告があれば送信しない。
空文や必須情報を失った定型文は投稿しない。意味が変わった可能性を `content_changed: true` で示す。
文章の意味保存やコードの動作は自動除去では保証しない。

## 誤検出とモデルの更新

珍しい公開名詞と非公開名詞を、情報量だけで確実に分けることはできない。
誤検出への基本的な対処は、投稿の一般化・除去、公開参照モデルの改善と再評価とする。
秘密値の登録や管理者による固有名詞の手動許可リストを、通常利用の必須手順にしない。
警告をその場で無視して送る機能も設けない。

送信者自身のpeer鍵、room ID、policy digest等は、プロトコルの型・署名・認可で検証する。
これらの必須メタデータを検証するcatalogは、投稿本文の語彙を手動許可する仕組みとは分ける。
本文の値に「公開hash」「UUID」等の型名を付けただけで検査を免除しない。
任意の証明URLを付けても、本文の公開性を確認したとは扱わない。

参照データ、モデル、走査方法、閾値表は署名済みbundleに固定する。
管理者は検証済みの版を導入するが、危険な値を一つずつ登録する必要はない。
agentや受信した投稿からモデル・policyを変更できないようにする。

## 校正と保証範囲

閾値は、候補のbyte長、文字列構造、周辺との差、モデルの不確実性ごとに評価して決める。
言語名をキーにした専用辞書・個別閾値は必須にしない。
評価時には言語・文字体系別の誤拒否率や見逃しも集計し、偏りを隠さない。

受入評価には、未登録の疑似token、短い秘密、人工的な未知名、珍しい公開名、
複数の文字体系、言語混在、URL内の値、符号化、繰返し、分割、埋草文による希釈、
モデル停止、処理上限、再送時のpolicy更新を含める。利用者の本物の秘密を評価用に持ち出さない。
固定の参照モデルを選定し、これらを評価するまでは検出精度を主張しない。

「秘密値を登録しなくても動く」と「未知の秘密をすべて検出する」は別である。
低エントロピーで一般的な表現の秘密、平凡な機密文、隠語、ステガノグラフィー、
複数peerやroomをまたぐ分割、送信時刻の符号化などは見逃し得る。
情報量を秘密の漏出bit数や機密確率として表示せず、完全な言語非依存精度も保証しない。
